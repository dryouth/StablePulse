# 0. CONTEXT SOURCE CONTRACT

Step 0 v13.3에서 아래 7개 source가 같은 thread에 이미 로드되어 있다.

- **S1 = `PYTHON_GROUND_TRUTH`**
- **S2 = `STABLECOIN_MARKET_INTELLIGENCE`**
- **S3 = `MACRO_NEWS_SUMMARY`**
- **S4 = `RRI_DASHBOARD`**
- **S5 = `ETH_SE_LEVEL_DASHBOARD`**
- **S6 = `CRCL_SE_LEVEL_DASHBOARD`**
- **S7 = `BTC_RELATED_ASSET_TECHNICAL_CONTEXT`**

Step 2에서는 이 7개 자료를 다시 요청하거나 재붙여넣도록 요구하지 않는다.

StablePulse issue number, reference date, report period 및 기타 metadata는 가능한 경우 S1 `PYTHON_GROUND_TRUTH`에서 직접 식별한다.

프롬프트의 StablePulse 번호를 매주 수동으로 수정하지 않는다.

S1에 issue number가 명시되어 있으면 그 값을 그대로 사용한다.

날짜·기간도 source에 이미 존재하는 값을 우선 사용하고, 동일 정보를 프롬프트에 다시 수동 입력하지 않는다.

# 0-3. 인용 원칙

• SE-Level Dashboard는 현재 적용 중인 Part A + Part B combined output을 사용한다. 특정 version 번호를 전제로 하지 않는다.

• Dashboard의 계산·판정 결과는 재계산·재구성·재판정하지 않는다. `PRICE_SOURCE / P_now / P_NOW_DATE`를 그대로 보존한다.

• Dashboard 전용 지표는 그대로 사용:
  - SE1/SE2/SE3 + provenance
  - TECHNICAL_KEY_LEVELS
  - CYCLE_ANCHORS
  - SE1_TESTED / Base Start / Support Hold
  - Part B Base Maturity /12 + Stage
  - Base Maturity Context / Context Count / Confidence
  - ATR(14) volatility regime (Daily + Weekly)
  - Volume MA(20) regime + expansion/spike/dry-up/capitulation/post-spike evidence
  - MAX_VOLUME_MA_EVENT_DIRECTION / LOCATION / CONTEXT
  - Breakout Reliability
  - DMR / Decline Structure
  - Cycle Position Metrics
  - Daily Price Action

• 추세의 최종 판정과 RSI·ADX·MACD·EMA 등 동일 지표의 수치는 리포트 기간 종료일 기준 S1 값을 우선한다.
  S5/S6의 Weekly/Daily Trend는 구조적 보조 확인용으로 사용하며 S1 Trend를 덮어쓰지 않는다.
  단, 모든 섹션의 기술적 수치·방향 판정에는 아래 V13.2 TECHNICAL COMPLETED-CANDLE EXCEPTION을 우선 적용한다.

• Part A EARLY_BASE_SCORE(/9)는 SE1 skip 판단용으로만 사용한다.

• 리포트의 메인 바닥 성숙도는 Part B의 통합 판정으로 사용한다:

`Total Maturity(/12) + Stage + Base Maturity Context + Base Maturity Confidence`

• /12 점수와 Stage는 구조적 core score이고,
  ATR(14)·Volume MA(20) 기반 Context/Confidence는 변동성 수축·거래량 소진·capitulation 후 정상화 여부를 확인하는 microstructure confirmation layer이다.

• 두 층을 분리 표기하되 최종 서술에서는 반드시 하나의 통합 Base Maturity 판단으로 결론낸다.

• Context는 /12 점수를 재계산하거나 가감하지 않는다.

• `UNCONFIRMED`는 4개의 supportive microstructure 조건 중 현재 충족된 것이 0개라는 뜻이다.
  시장 전체가 중립이라는 의미가 아니며, 강한 bullish/bearish volume expansion이 동시에 존재할 수 있다.

• Context와 현재 Volume Regime을 서로 치환하거나 모순으로 취급하지 않는다.

• S5/S6에 없는 가격 level·지표·판정은 추정하거나 재구성하지 않는다.

## 0-3A. V13.2 HARD ROUTING AND COMPLETED-CANDLE LOCK — HIGHER PRIORITY

이 subsection은 기존 분석 framework를 삭제하거나 바꾸지 않고, source retrieval과 기술지표 기준시점의 모호성만 제거한다. 아래 규칙이 기존의 일반 source-priority·출력 규칙과 충돌하면 이 subsection이 우선한다.

### A. S1 EXACT PATH LOCK

- 섹션 4의 BTC/ETH DAT는 S1 → Investment Insights → Macro → Use data like의 BTC_CorpTreasury / ETH_CorpTreasury를 읽는다. native holding 수량, USD 평가액, 7d, 30d를 같은 field에서 함께 보존한다.
- 섹션 5 온체인의 발행사 점유율은 S1 → Investment Insights → DeFiRWA → Use data like의 USDTShare / USDCShare를 읽는다.
- 이더리움 체인 점유율은 같은 줄의 EDSStablecoin을 사용한다. EDSStablecoin은 chain share, USDTShare/USDCShare는 issuer share이므로 서로 바꾸지 않는다.
- field의 S1 내 물리적 위치와 리포트 사용 section이 다르다는 이유로 누락하거나 다른 section으로 보내지 않는다.
- Step 0 routing index에서 PASS한 field에는 미제공, 단위 불명확, 비교 유보, 별도 확인 필요라고 쓸 수 없다.

### B. TECHNICAL COMPLETED-CANDLE EXCEPTION

리포트 전 섹션의 기술적 수치·방향·AGREE/CONFLICT 판정에서는 S5/S6의 TradingView CSV 기반 완성봉 지표가 최종 Ground Truth다. 이는 동일 기술지표에서 S1을 우선한다는 기존 일반 규칙의 명시적 예외다. S1의 가격·시장·온체인·밸류에이션 Ground Truth 우선순위는 그대로 유지한다.

S5와 S6는 분석 방식이 full 또는 incremental인지와 무관하게 동일한 consumer schema를 사용한다. 각 section 상단의 `TECHNICAL_COMPLETED_CANDLE_LOCK: PASS`, `ANALYSIS_MODE: FULL` 또는 `INCREMENTAL_FULL_SCHEMA`, `SOURCE_CLASS: TRADINGVIEW_CSV`, Daily/Weekly source file, `DAILY_ENDPOINT_LOCK`, `WEEKLY_ENDPOINT_LOCK`, `CURRENT_WEEK_INFORMATIONAL_EXCLUDED: TRUE`, `SOURCE_LOCK_SUMMARY: SOURCE_FILES PRESENT | ENDPOINT_VALIDATION TRUE | PART_A_SOURCE_LOCK TRUE`, `REQUIRED_COMPLETED_CANDLE_FIELDS_VALIDATION: ALL PRESENT`를 먼저 확인한다.

고정 required completed-candle fields는 `DAILY_ADX_DI_RSI`, `WEEKLY_ADX_DI_RSI`, `DAILY_MA_VALUES`, `DAILY_KUMO`, `WEEKLY_KUMO`, `DAILY_ATR`, `WEEKLY_ATR`, `DAILY_VOLUME`, `WEEKLY_VOLUME`의 9개뿐이다. 이 lock과 9개 field가 모두 통과하면 다른 선택 지표의 부재를 이유로 completed-candle 오류를 만들지 않는다.

- Daily 기준: DAILY_ENDPOINT에 표시된 마지막 완결 일봉. 통상 리포트 종료일인 월요일이다.
- Weekly 기준: WEEKLY_ENDPOINT에 표시된 가장 최근 완결 주봉.
- CURRENT_WEEK_INFORMATIONAL 및 다운로드 시점의 진행 중 일봉·주봉은 본문 판정과 수치 인용에서 제외한다.
- S5/S6의 DAILY_ADX_DI_RSI, WEEKLY_ADX_DI_RSI, DAILY_MA_VALUES, DAILY_KUMO, WEEKLY_KUMO, DAILY_ATR, WEEKLY_ATR, DAILY_VOLUME, WEEKLY_VOLUME 및 존재하는 finalized technical fields만 사용한다.
- S1의 RSI/ADX/MACD/EMA 등 Python 기술지표와 리포트 작성 시점의 live 지표는 REFERENCE_ONLY다. 본문 수치, AGREE/CONFLICT 판정, Step 5 확인사항의 기준으로 사용하지 않는다.
- S1 또는 live 값과 S5/S6 완성봉 값이 다른 것은 EXPECTED_SOURCE_TIME_DIFFERENCE이며 오류나 충돌이 아니다.
- S5/S6의 `TECHNICAL_COMPLETED_CANDLE_LOCK`이 PASS가 아니거나, `SOURCE_LOCK_SUMMARY`가 위 PASS 형식이 아니거나, 위 고정 9개 field 중 실제 누락이 있을 때만 S1 값으로 대체하지 않고 페이지 쓰기를 중단한다. 오류는 `CONTEXT_ERROR: [S5 또는 S6]:TECHNICAL_COMPLETED_CANDLE_LOCK:[실제 누락 또는 실패 field]`로 출력한다. `ANALYSIS_MODE: INCREMENTAL_FULL_SCHEMA` 자체와 선택 지표 부재는 오류가 아니다.
- SE-Level, TECHNICAL_KEY_LEVELS, CYCLE_ANCHORS, Base Maturity, Breakout Reliability 등 기존 S5/S6 finalized 구조 판정은 그대로 유지한다.

TRUE_TECHNICAL_CONFLICT는 동일 자산·동일 지표·동일 타임프레임·동일 완성봉 날짜·동일 source class 안에 서로 다른 값이 있을 때만 성립한다.

### C. S4 FINALITY AND NEGATIVE-CLAIM GATE

- S4에 RRI Total, MCPO Phase, Distribution Triggers total과 T1–T5가 있으면 그 값으로 국면을 확정한다. 별도 Action Mode 또는 finalized action을 요구하지 않으며, MCPO Phase가 Distribution이면 기존 규칙에 따라 WAIT를 유지한다.

- 미제공, 불명확, 유보, 확인 필요, 미입력, 별도 확인이라는 문구를 쓰기 전에 Step 0 routing index와 S1–S7의 canonical field를 다시 확인한다.

### D. COVERAGE WITHOUT BLOAT

## 섹션 7 투자 노트 레벨 출처

### 진입 앵커
SE1 / SE2 / SE3

### 구조적 지지·저항
TECHNICAL_KEY_LEVELS  
→ Support / Resistance의 1차 기준

### 사이클 맥락
CYCLE_ANCHORS  
→ Active Cycle Peak / Trough 장기 구조 확인용

### 단기 보조
S1 Sup/Res, EMA/VWMA, Kumo, Fib 등  
→ 상위 세 범주에 없는 단기 모니터링 정보가 있을 때만 선택적으로 사용

### Base

리포트 메인 판정은 Integrated Base Maturity:

1. Part B Total Maturity /12 + Stage = 구조적 core score
2. Base Maturity Context Count / Context = ATR·Volume microstructure confirmation
3. Base Maturity Confidence = 두 층을 결합한 최종 신뢰도 라벨

SE1_TESTED / Base Start / Support Hold도 함께 확인한다.

Part A EARLY_BASE_SCORE(/9)는 SE1 skip 판단용 별도 지표다.

리포트 메인 Base Maturity와 혼용하지 않는다.

SE1_TESTED=FALSE이면 실제 SE1 base가 형성되었다고 서술하지 않는다.

ATR contraction은 안정화에 우호적일 수 있으나 단독 바닥 신호가 아니다.

Volume expansion/spike는:
- 캔들 방향
- 저점 위치

와 함께 해석한다.

downside capitulation 이후:
- volume contraction
- dry-up

이 나타나는지를 우선 확인한다.

ATR expansion 또는 volume spike만으로 바닥 성숙도를 상향하지 않는다.

`MAX_VOLUME_MA_EVENT_CONTEXT` 해석:

- BULLISH_PARTICIPATION → 강한 상승 참여 확인
- BEARISH_PARTICIPATION → 강한 하락 참여 확인
- CAPITULATION_CANDIDATE → 저점 인접 대량 하락 이벤트, 이후 hold/contraction 확인 필요
- FLAT_PARTICIPATION → 방향성 제한

이 이벤트 해석은 Context Count를 재계산하거나 변경하는 근거로 사용하지 않는다.

### Breakout

S5/S6 Breakout Reliability의 finalized label을 그대로 사용한다.

별도로 재판정하지 않는다.

- 장기 가치 평가 적정가
- TECHNICAL_KEY_LEVELS
- CYCLE_ANCHORS
- 필요한 경우 단기 보조 레벨

### ③ 두 자산의 Integrated Base Maturity

- /12 Stage
- Context
- Confidence
- SE1_TESTED
- Breakout Reliability

를 비교·종합하여 포지셔닝 판단으로 마무리한다.

가능하면 ATR regime과 Volume/VolumeMA20 상태의 차이도 1문장으로 비교한다.

Base Maturity 표기 우선 형식:

`[X]/12 [EARLY/MID/MATURE] · Context [SUPPORTIVE/MIXED/UNCONFIRMED] ([N]/4) · Confidence [state]`

`UNCONFIRMED`가 있더라도 bullish/bearish participation이 강하면 별도로 병기한다.
