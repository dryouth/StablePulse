## V13.2 SOURCE AND TECHNICAL QA OVERRIDES — HIGHER PRIORITY

이 subsection은 기존 one-pass·surgical-edit 원칙을 유지하면서 반복되는 false missing claim과 서로 다른 기준시점의 기술지표를 오류로 취급하는 문제만 막는다. 충돌 시 아래 규칙이 우선한다.

### 1. EXACT S1 ROUTING AUDIT

- BTC/ETH DAT는 S1 → Investment Insights → Macro → Use data like의 BTC_CorpTreasury / ETH_CorpTreasury와 대조한다.
- 발행사 점유율은 S1 → Investment Insights → DeFiRWA → Use data like의 USDTShare / USDCShare와 대조한다.
- 체인 점유율은 EDSStablecoin과 대조한다.
- 위 field가 있으면 미제공·단위 불명확·비교 유보라는 문장을 명백한 source-fidelity 오류로 보고 해당 값을 사용하도록 surgical proposal을 만든다.

### 2. NEGATIVE ASSERTION AUDIT — REQUIRED EXCEPTION

본문의 미제공, 불명확, 유보, 확인 필요, 미입력, 별도 확인을 모두 검색한다. 이 문장들에 대해서만 PASS B의 본문 등장값 제한을 해제하고 S1–S7의 지정 경로를 source-wide로 다시 확인한다. 값이 있으면 확인 필요로 남기지 않는다.

### 3. TECHNICAL SOURCE PRECEDENCE

- 기술적 수치와 일간/주간 AGREE·CONFLICT는 S5/S6의 TradingView CSV 기반 DAILY_ENDPOINT·WEEKLY_ENDPOINT 완성봉 field만 검증한다.
- CURRENT_WEEK_INFORMATIONAL, S1 Python 기술지표, 리포트 작성 시점 live 값은 REFERENCE_ONLY다.
- S1/live와 S5/S6 완성봉의 차이는 EXPECTED_SOURCE_TIME_DIFFERENCE이며 REVIEW PROPOSAL이나 확인 필요에 넣지 않는다.
- TRUE_TECHNICAL_CONFLICT는 동일 자산·지표·타임프레임·완성봉 날짜·source class에서 값이 다를 때만 성립한다.
- SOURCE_FILES, ENDPOINT_VALIDATION 또는 PART_A_SOURCE_LOCK 실패는 실제 확인 필요다. 이때 다른 source 값으로 대체하지 않는다.
- S5/S6의 `TECHNICAL_COMPLETED_CANDLE_LOCK: PASS`와 `REQUIRED_COMPLETED_CANDLE_FIELDS_VALIDATION: ALL PRESENT`가 있으면 완성봉 source gate를 통과한 것으로 간주한다. 고정 required 9개 외 선택 지표의 부재로 추가 확인사항을 만들지 않는다.
- 섹션 7의 Active Cycle Peak/Trough와 모든 사이클 앵커는 S5/S6의 `CYCLE_ANCHORS`만 정본으로 사용한다. S4의 `ETH_Cycle` Peak/MDD는 RRI 산정용 cycle-duration·drawdown 맥락이며 섹션 7 기술적 앵커의 source가 아니다.
- S4 `ETH_Cycle`과 S5/S6 `CYCLE_ANCHORS`를 서로 대조해 충돌·확인 필요를 만들지 않는다. source class·timeframe·목적이 다르므로 값이나 날짜 차이는 `EXPECTED_SOURCE_TIME_DIFFERENCE`로 처리한다.
- ETH 백미러 부록의 과거 기술 주장에는 현재 S5/S6를 적용하지 않는다. Step 3 v13.2의 historical completed-candle source lock을 따르며, 현재 값과 과거 값을 비교해 충돌을 만들지 않는다.

### 4. S4 FINALITY

S4의 RRI Total, MCPO Phase, Distribution Triggers total과 T1–T5가 있으면 추가 방향 판별 조건이나 별도 Action Mode/finalized action을 요구하지 않는다. MCPO Phase가 Distribution이면 기존 규칙에 따라 WAIT를 유지하며, 자산별 최대낙폭 발동 개수 미제공 같은 새로운 확인사항을 만들지 않는다.

- Chain App Revenue에 R 또는 ORGANIC/INCENTIVE/MIXED가 독자용 본문에 노출되면 가속·비슷·둔화와 의의 중심 자연어로 바꾸는 proposal을 만든다.
